# 4.1 Projects

A project is a folder. File > Open Folder… (Cmd+O / Ctrl+O) opens one, and File > Open Recent lists the folders opened
before. The IDE reads every file below the folder, decides from each file name what kind of file it is, and groups the
model files into contexts that are checked and run together.

## 4.1.1 Kinds of files

The kind of a file follows from its name alone.

| Name | Kind | Reference |
|---|---|---|
| `*.kmeta` | Domain metamodel | [2.1 KMeta](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.1-kmeta.md) |
| `EVENTS.kmeta`, in any case | Event metamodel | [2.1 KMeta](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.1-kmeta.md) |
| `*.kmodel` | Model | [2.2 KModel](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.2-kmodel.md) |
| `*.kstates` | State machine | [2.3 KStates](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.3-kstates.md) |
| `*.kenv.json` | Environment descriptor | [4.1.2 Environment descriptors](#412-environment-descriptors) |
| `*.kbridge.json` | Bridge | [4.7 Bridges](4.7-bridges.md) |
| `*.vis` next to a model file | Layout of a diagram, written by the IDE | [4.3 Diagrams](4.3-diagrams.md) |
| `.karpfenproject` | Project file | [4.1.6 The project file](#416-the-project-file) |

An event metamodel can also have another name, such as `lamp-events.kmeta`, when a descriptor names it under `events`.

The IDE leaves out these folders: `.git`, `.gradle`, `build`, `out`, `.idea`, `.kotlin`, `node_modules`,
`karpfen-runs` and every folder whose name starts with a dot.

## 4.1.2 Environment descriptors

An environment descriptor is a JSON file named `*.kenv.json`. It says which metamodel, event metamodel, model and state
machines form one context, which object of the model each state machine is attached to, and how fast the model runs.
A descriptor is what Run starts. The paths in it are relative to the folder of the descriptor and must lie inside the
project.

### 4.1.2.1 Keys

| Key | Value | Meaning |
|---|---|---|
| `metamodel` | String, required | The domain metamodel, a `.kmeta` file. |
| `events` | String or `null` | The event metamodel, a `.kmeta` file. Without it the context has no events. |
| `model` | String, required | The model the runtime starts from, a `.kmodel` file. |
| `stateMachines` | List of objects | The state machines. Each entry has `file`, a `.kstates` file, and `attachedTo`, the key of the object it runs on. The type of that object should be the type after `ATTACHED TO` in the state machine. Without the key the list is empty. |
| `tickDelayMs` | Number | The time in milliseconds between two ticks. Without the key it is 50. |
| `eventTtlMs` | Number | How long in milliseconds an event waits for a state machine that takes it. 0 keeps events until a state machine takes them. Without the key it is 3000. |
| `observe` | Object | `objects`, required, with `"*"` for every object, and `domains`, a list of event domains. A run does not use it, because the IDE observes the whole model and listens to every domain the state machines use. |
| `runtime` | Object | `image` and `pythonPackages`. A run does not use it, because the IDE runs every model in its own container. |
| `bridges` | List of strings | Bridge files. A run does not use it. The run dialog chooses the bridges, see [4.5 Running](4.5-running.md). |

The editor reports these problems in a descriptor.

| Code | Severity | Cause |
|---|---|---|
| `descriptor-missing-file` | Error | A named file does not exist, lies in a left-out folder or lies outside the project. |
| `descriptor-invalid` | Error | A named file is of the wrong kind for its key, a value is of the wrong kind, a required key is missing, or a key is written twice. |
| `descriptor-unknown-key` | Warning | The key is not one of the table above. |
| `deploy-observe-superseded` | Info | The descriptor has `observe`. |
| `deploy-hosting-ignored` | Info | The descriptor has `runtime` or `bridges`. |
| `deploy-tick-delay-range` | Error | `tickDelayMs` is below 0 or above 2147483647. |
| `deploy-tick-delay-zero` | Warning | `tickDelayMs` is 0, so the runtime never waits between ticks. |
| `deploy-event-ttl-never-expires` | Info or warning | `eventTtlMs` is 0, an info, or negative, a warning. Events then never expire. |

### 4.1.2.2 A minimal descriptor

This descriptor runs the lamp with only its own state machine.

```json
{
  "metamodel": "lamp.kmeta",
  "events": "lamp-events.kmeta",
  "model": "lamp.kmodel",
  "stateMachines": [
    { "file": "lamp.kstates", "attachedTo": "lamp" }
  ]
}
```

The descriptor of the example in `examples/lamp` also attaches `switch.kstates` to `wallSwitch` and sets the timing:

```json
{
  "metamodel": "lamp.kmeta",
  "events": "lamp-events.kmeta",
  "model": "lamp.kmodel",
  "stateMachines": [
    { "file": "lamp.kstates", "attachedTo": "lamp" },
    { "file": "switch.kstates", "attachedTo": "wallSwitch" }
  ],
  "tickDelayMs": 500,
  "eventTtlMs": 5000
}
```

### 4.1.2.3 Creating a descriptor

Right-click a folder in the Project tool window and choose New Environment File. A dialog asks for the name, and
`.kenv.json` is added. The new descriptor names the files of the folder's current context: the metamodel, the events,
the first model and every state machine. Each state machine is attached to the first object of its `ATTACHED TO`
type, otherwise to the first object of the model, and otherwise to the placeholder `"object"`. When the state machines
use event domains, the descriptor also gets an `observe` key, which a run does not use. The timing keys are left out,
so the defaults hold.

## 4.1.3 Folders without a descriptor

A folder without a descriptor forms a context of its own from the karpfen files directly inside it that no
descriptor names. Its metamodel is the one `.kmeta` file that is not `EVENTS.kmeta`, its event metamodel is
`EVENTS.kmeta`, and its models and state machines are all `.kmodel` and `.kstates` files of the folder. Such a context
is checked like any other, but it cannot be run, because Run needs a descriptor.

| Situation | Finding |
|---|---|
| Several `.kmeta` files other than `EVENTS.kmeta` | The info `context-multiple-metamodels` on each of them. The first in alphabetical order, ignoring case, is the metamodel. The others belong to no context. |
| No `.kmeta` file other than `EVENTS.kmeta` | The info `context-no-metamodel` on each model and state machine. |

A folder that holds a descriptor forms no context of its own. Its karpfen files that no descriptor names belong to no
context.

## 4.1.4 Files that belong to no context

A file that belongs to no context is still checked. A state machine is read on its own, with the language features of
the project, and its errors block a run like any other. A model or a metamodel is checked for its syntax only.

## 4.1.5 The project tree

The Project tool window shows the folder in three sections, divided by lines.

1. The project file `.karpfenproject` and the environment descriptors.
2. The folder with the model files and their subfolders.
3. The bridge files.

A double-click or Enter opens a file. A bridge file opens in its form. The `.vis` file of a diagram shows below its
model file, which can then be expanded, and opens as text that cannot be edited.

The context menu of the tree has these entries.

| Entry | Effect |
|---|---|
| New KMeta File, New KModel File, New KStates File, New Environment File | Asks for a name and creates the file in the folder of the entry, with the suffix added. A new file reads without errors in its context. |
| Rename… | Renames the file or folder. Not for the project folder itself. |
| Delete… | Deletes the file or folder. Not for the project folder itself. |
| Reveal in Finder, Show in Explorer or Show in File Manager | Shows the file in the file manager of the system. |

Renaming a file does not change the descriptors or the other files that name it.

## 4.1.6 The project file

The file `.karpfenproject` in the folder holds the settings of the project. The IDE writes it when one of its values
changes, so a folder that was never changed has none. It is plain text with one `key = value` per line. A line that
starts with `#` is a comment. The file can be edited by hand and kept in version control.

```text
# karpfen project settings. karpfen IDE reads and rewrites this file.
theme = dark
zoom = 110
editorFontSize = 14
pane.runtime = shown 400
open = lamp.kstates
open = lamp.kmeta
active = lamp.kstates
bridge = http.kbridge.json
capture = on
feature.history = on
```

| Key | Value |
|---|---|
| `theme` | `light`, `dark` or `system`. |
| `zoom` | The scale of the whole window in percent, from 70 to 200. |
| `editorFontSize` | The font size of the editors, from 8 to 40. The default is 13. |
| `pane.project`, `pane.outline`, `pane.problems`, `pane.output`, `pane.runtime` | `shown` or `hidden`, then the size of the tool window. The default sizes are 260, 240, 200, 180 and 400. `pane.output` is the Language Tools Output. |
| `open` | An open file, relative to the folder. One line per tab, in the order of the tabs. |
| `active` | The file of the active tab. |
| `bridge` | A bridge that was ticked in the last run dialog. One line per bridge. |
| `capture` | `on` when Capture run to file was ticked in the last run dialog. Without the line it is off. |
| `feature.<id>` | `on` for a language feature that is switched on, see [4.1.7 Language features](#417-language-features). Without the line the feature is off. |

A value that makes no sense is dropped, and the default holds. A line with a key the IDE does not know is kept when the
IDE writes the file.

## 4.1.7 Language features

Five parts of KStates are optional. Each project switches them on by hand, and all are off in a new project.

| Feature | Id in `.karpfenproject` | Reference |
|---|---|---|
| Histories | `history` | [2.3.7 Histories](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.3-kstates.md#237-histories) |
| Tick limits | `tickLimit` | [2.3.8 Tick limits](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.3-kstates.md#238-tick-limits) |
| Breakpoints | `breakpoints` | [2.3.9 Breakpoints](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.3-kstates.md#239-breakpoints) |
| Macros | `macros` | [2.3.6 Macros](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.3-kstates.md#236-macros) |
| Splits and joins | `parallel` | [2.3.4.3 Splits and joins](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/reference/2.3-kstates.md#2343-splits-and-joins) |

Run > Language Features has one entry per feature. It says what a click does, such as `Switch On Histories` or
`Switch Off Histories`. The IDE writes the change into `.karpfenproject` as a line such as `feature.history = on`, and
an edit of that line by hand has the same effect.

While a feature is off, every use of it in a state machine is the error `kstates.feature-off`, and a run is blocked.
Completion and the menus of the statechart do not propose the feature. A run switches on the runtime features that the
project needs: History for histories, TickLimit for tick limits and Breakpoint for breakpoints, see
[3.2 Runtime features](https://github.com/karpfenproject/karpfen-runtime/blob/main/docs/reference/3.2-features.md).
With breakpoints on, a run has a debugger, see [4.6 Debugging](4.6-debugging.md).

## 4.1.8 Settings and logs outside the project

Only the recent folders and the place and size of the window are kept outside the project, in
`~/.karpfen-ide/settings.json`. The log of the IDE is `~/.karpfen-ide/logs/ide.log`, and the log of the language
tools is `~/.karpfen-ide/logs/dsl-tools.log`. The environment variable `KARPFEN_IDE_HOME` names another folder for
both.
