# 4.8 Command line

The IDE also works in a terminal, without a window. `validate` checks a project and ends. `run` validates a project,
runs it with its bridges in the IDE's Docker container and prints what happens until it is stopped.

## 4.8.1 Commands

```text
Usage:
  karpfen-ide [<folder>]
  karpfen-ide validate <folder> [--format text|json]
  karpfen-ide run <folder> [--descriptor <file>] [--bridge <file>]... [--capture]
                                [--true-parallel] [--verbose]
```

| Command | Effect |
|---|---|
| `karpfen-ide <folder>` | Opens the window on the folder. Without a folder the window opens on its welcome view. |
| `karpfen-ide validate <folder>` | Validates the whole project, prints the findings and ends. |
| `karpfen-ide run <folder>` | Validates the project, runs it and prints what happens until it is stopped. |
| `karpfen-ide validate --help`, `karpfen-ide run --help` | Prints the usage and ends with status 0. `-h` does the same. |

Options may stand before or after the folder. A value follows its option as the next argument or after `=`, as in
`--bridge=http.kbridge.json`. `--` ends the options, so a folder after it may start with `-`. A folder that is itself
named `validate` or `run` must be written with a path in front, as in `./run`, when it is the first argument.

A wrong command line prints `karpfen-ide:` and what is wrong, then the usage, on the error output, and ends with status
2. Wrong are an unknown option, a missing, second or empty folder, a folder that does not exist, an option without its
value, a second `--descriptor` or `--format`, a format other than `text` or `json`, a bridge named twice, and an option
that the command does not take.

```text
karpfen-ide: unknown option '--frmat'
```

## 4.8.2 Starting it

| From | Command |
|---|---|
| The sources | `./gradlew :app:ide:run --args="validate /absolute/path/to/project"` |
| The application on macOS | `karpfen-ide.app/Contents/MacOS/karpfen-ide validate <folder>` |
| The application on Linux | `karpfen-ide/bin/karpfen-ide validate <folder>` |
| The application on Windows | `karpfen-ide\karpfen-ide.exe validate <folder>` |

From the sources the folder must be an absolute path. `./gradlew :app:ide:createDistributable` builds the application
into `app/ide/build/compose/binaries/main/app/`. On Windows the application is built with a console, so the commands
have somewhere to print, and opening the window by a double-click also opens a console window.

## 4.8.3 Validating

```bash
karpfen-ide validate examples/lamp
```

The command runs the same checks as Validate in the window, see [4.4 Validating](4.4-validating.md). It prints one line
per finding, errors first, and then a summary. A project without findings prints `No problems found.`

```text
lamp.kstates:13: error: mismatched input 'STATMACHINE' expecting 'STATEMACHINE'
switch.kstates:8: warning: This EVAL has no return, so it yields no value; return the value it computes
1 error and 1 warning
```

With `--format json` it prints one JSON document instead, for a program to read.

```bash
karpfen-ide validate examples/lamp --format json
```

```json
{
    "root": "/home/me/karpfen-IDE/examples/lamp",
    "errorCount": 1,
    "warningCount": 1,
    "problems": [
        {
            "path": "lamp.kstates",
            "line": 13,
            "column": 1,
            "severity": "error",
            "message": "mismatched input 'STATMACHINE' expecting 'STATEMACHINE'",
            "code": "syntax-error"
        },
        {
            "path": "switch.kstates",
            "line": 8,
            "column": 33,
            "severity": "warning",
            "message": "This EVAL has no return, so it yields no value; return the value it computes",
            "code": "kstates.eval-without-return"
        }
    ]
}
```

| Member | Meaning |
|---|---|
| `root` | The folder of the project, as an absolute path. |
| `errorCount`, `warningCount` | How many errors and warnings the project has. |
| `problems` | The findings, sorted by path, line and column. |
| `path` | The file, relative to the folder. |
| `line`, `column` | Where the finding starts. Both count from 1. |
| `severity` | `error`, `warning`, `info` or `hint`. |
| `message` | What is wrong, in words. |
| `code` | The stable name of the kind of finding. |

## 4.8.4 Running

```bash
karpfen-ide run examples/lamp --descriptor lamp.kenv.json --bridge http.kbridge.json --capture
```

| Option | Meaning |
|---|---|
| `--descriptor <file>` | The descriptor to run, relative to the folder or absolute. It can be left out when the project has exactly one. |
| `--bridge <file>` | A bridge file of the project to start with the run. Give the option once per bridge. Without it no bridge starts. |
| `--capture` | Writes the log of the run to a file in `karpfen-runs/`, as Capture run to file does in the window, see [4.5.8 Captured logs](4.5-running.md#458-captured-logs). |
| `--true-parallel` | Steps the branches of a split on threads of their own, as the box TrueParallel does in the run dialog, see [4.5.3 The run dialog](4.5-running.md#453-the-run-dialog). The project must have splits and joins switched on. |
| `--verbose` | Also prints every line of the runtime's log. |

The choice of files is checked against the project, and a wrong choice ends with status 2, a message and the usage.

| Case | Message |
|---|---|
| The project has no descriptor. | `the project has no environment descriptor (*.kenv.json)` |
| The project has several descriptors, and `--descriptor` is missing. | `the project has several environment descriptors; choose one with --descriptor:` and the list |
| `--descriptor` names no descriptor of the project. | `<file> is no environment descriptor of the project;` and the list |
| `--bridge` names no bridge file of the project. | `<file> is no bridge file of the project;` and the list |
| `--true-parallel` is given, and splits and joins are off. | `--true-parallel needs splits and joins switched on for the project (feature.parallel = on in .karpfenproject)` |

A run goes through these steps.

1. It validates the whole project. With an error it prints the findings as `validate` does and does not run. With
   warnings only it prints them the same way, then `The run goes on despite the warnings.`, and runs.
2. It starts the runtime in the IDE's Docker container. The first run builds the runtime image.
3. It deploys the descriptor and starts the bridges.
4. It prints what happens until you stop it with Ctrl+C or a terminate signal.
5. It stops the bridges and the environment, removes the runtime container and ends.

This is what a run of the lamp with one bridge prints. The switch is pressed once through the bridge, and then the run
is stopped. The first run prints a line for each step of building the image as well.

| Line | Status |
|---|---|
| `The run does not start: the project has errors.` | 1 |
| `The run did not start.` | 3 |
| `The run does not start: the deployment is blocked.` | 3 |
| `The run failed.` | 3 |
| `The run ended on its own.` | 3 |

## 4.8.5 What a run reads from the project

A run without a window takes one thing from `.karpfenproject`: which optional language features are on. Everything else
in that file, such as the bridges ticked in the window, is ignored. Nothing is written, neither to `.karpfenproject` nor
to the settings of the user. A run without a window has no debugger, so breakpoints never halt it, also when the project
has them switched on. It has no time limit and ends only when it is stopped.

## 4.8.6 Exit statuses

| Status | Meaning |
|---|---|
| 0 | The validation found no error. Warnings are allowed. Also after `--help`. |
| 1 | The project has errors. A run did not start. |
| 2 | The command line was wrong. A message and the usage are printed. |
| 3 | A run could not start, failed or ended on its own, or the folder could not be opened as a project. |

A run that is stopped by a signal ends with the status the system gives a process that got that signal. A run started
through Gradle therefore makes the Gradle task fail when it is stopped.
