# 4.2 Text editor

Every karpfen file and every environment descriptor opens in the text editor, with one tab per file. The editor checks
the text while you type. Since it knows the names declared in the project, it can complete them, explain them and lead
from a name to its declaration.

Where a key differs between the systems, the key for macOS is written first and the key for Windows and Linux second,
for example Cmd+S / Ctrl+S.

## 4.2.1 Colours and marks

The editor colours keywords, the action operations such as `SET` and `DROPOBJ`, strings, numbers, operators and
comments. The names of attachable state machines have a colour of their own. Such a name stands after `STATEMACHINE`,
`behaves after` and `ATTACH`, and it is the second argument of `EXCHANGE`.

The code inside an `EVAL` block is Python, and the editor colours it as Python with its own keywords, strings, numbers
and `#` comments. In that code it also marks the model paths `$(...)` and the macro references `@name`. A descriptor is
coloured as JSON.

Errors and warnings get a wavy underline, infos a dotted one. The gutter shows the line numbers and a marker on each
line with a problem. Resting the mouse on an underlined place shows the problem.

Brackets and quotes are closed as you type them. The bracket that matches the one at the caret is marked.

## 4.2.2 Completion

Completion opens by itself after two letters of a word, after an opening quote, after `$(` and after `->`. The menu
entry *Complete Code* opens it by hand. Its key is Ctrl+M on every system, and on macOS too it is pressed with the
Control key. On Windows Ctrl+Space works as well.

In the list, the arrow keys and Page Up and Page Down move to an item, and Enter, Tab or a double-click takes it.
Escape closes the list.

An item marked *template* inserts a whole declaration of several lines. It stands in the list behind the short item
of the same keyword. The names and values to fill in are placeholders, and the first one is selected.

| Key | Effect while the placeholders are active |
|---|---|
| Tab | Selects the next placeholder. After the last one it puts the caret behind the declaration. |
| Shift+Tab | Selects the placeholder before. |
| Escape | Ends the placeholders. Tab indents again. |

A click or an edit outside the declaration ends the placeholders as well. One undo removes the whole declaration.
Completion works on a selected placeholder, and the item taken replaces it.

| File | Templates |
|---|---|
| KMeta | A type with a property, a `has` relation and a `knows` relation. In an event metamodel the type has a property and a `has` relation. |
| KModel | An object of each type of the metamodel, with every property and relation of the type. A property gets an empty text, `0` or `false` by its type. A `has` relation gets the object of its target type with that type's members. A list gets one entry. A key that the file uses already gets a number. The same objects are offered after `has("…") -> ` followed by a blank. In the body of an object each `has` relation that the object lacks is offered with its object. Without a metamodel one object with one property is offered. |
| KStates | A state machine with two states and a transition. A fragment with a final state. A state with an `ENTRY` and a `DO` block. A container state with its fragment. A transition that waits for an event. A split, a join and a macro, each only while its language feature is on. |

| File | What completion proposes |
|---|---|
| KMeta | The `type` block at the top level. `prop`, `has`, `knows` and `list` in a type. `number`, `string` and `boolean` as the type of a property. The types of the file at the type of a relation, and in an event metamodel also the domain types. `behaves after "…"` after the description of a type, and inside its string the attachable state machines of the context, with those attachable to the type first. |
| KModel | The `make object` block before the root object. `prop`, `has` and `knows` in an object. The properties and relations of the object's type inside `prop("`, `has("` and `knows("`. The types at `make object "key":"`, with the target type of the relation first. The keys of the objects of a fitting type after `knows("relation") -> "`. |
| KStates | The keywords that fit the place, the action operations, `IF IN SCOPE` and `WITH ... AS`. The states inside the strings of a transition. The domain types after `ATTACHED TO "` and `ATTACHABLE TO "`. After `STATEMACHINE` the attached and the attachable header. `ATTACH "…"` after the parentheses of `SETOBJ` and `APPENDOBJ`. The attachable state machines of the context after `ATTACH "` and in the second argument of `EXCHANGE(`, with those attachable to the type at that place first. The paths of the model in the strings of actions, `VALUE`, `IF IN SCOPE` and macro arguments, and after `$(` in `EVAL`. The events in the second argument of `EVENT(`, and the event domains used in the file. The macros inside `MACRO("` and after `@`. `CONTAINER STATE "…" USE "…"` among the states and in a state, `FINAL STATE "…"` among the states, `STATEMACHINE "…" FRAGMENT` as a header and `DONE` in a condition. The fragments of the project after `USE "`, with those of the context first and without the fragment of the file itself. The constructs of an optional language feature only while the feature is on. |
| Descriptor | In an empty file the descriptor with its required keys. The keys an object does not have yet, with their documentation. The files that fit a key, with those next to the descriptor first. The object keys of the model at `attachedTo`, with the fitting ones first. The event domains of the state machines. Typical values of `tickDelayMs` and `eventTtlMs`. |

## 4.2.3 Hover

Resting the mouse on a name shows what the name stands for and the problems at that place.

| File | What hover shows |
|---|---|
| KMeta | The type, or a property with its type, such as `prop maxWatts: number`. The state machine after `behaves after` with its types. |
| KModel | The type of an object, a property or relation with its type, or an object with its key and type. |
| KStates | A state with its path, such as `state on > full`, a macro with its signature, the type a path leads to, or the type or event a name stands for. An attachable state machine with its types, such as `state machine "glowing" attachable to Bulb`. The fragment after `USE` with its file, such as `fragment "bulb_test" in bulb_test.frag.kstates`. |
| Descriptor | What a key means, the role of a named file, the object behind `attachedTo` with its type, and an event domain. |

## 4.2.4 Go to definition

The menu entry *Go to Definition* leads from a name to its declaration, also when the declaration is in another
file. Its keys are Cmd+B / Ctrl+B and Cmd+click / Ctrl+click.

| From | To |
|---|---|
| The type after `ATTACHED TO` in a state machine | The type in the metamodel. |
| A state name in a transition | The state. A state leads back to the places that name it. |
| A macro name | The macro. |
| The name of a state machine after `behaves after`, `ATTACH` or in `EXCHANGE(` | The attachable state machine, in its own file. |
| The name of a fragment after `USE` | The header of the fragment, in its own file. A fragment of the context of the file wins over one of another context. |
| An event name in `EVENT(` | The event type in the event metamodel. |
| A segment of a model path | The property or relation in the metamodel. |
| A type or a property or relation key in a model | Its declaration in the metamodel. |
| The target key of `knows` in a model | The object with that key. |
| A file path in a descriptor | The file. |
| The value of `attachedTo` in a descriptor | The object in the model. |

The IDE has no search for the places that use a name.

## 4.2.5 Outline

The *Outline* tool window shows what the active file is made of. It has one row per element in the form
`name : detail`, nested like the text.

| File | Rows |
|---|---|
| Metamodel | The types with their properties and relations. |
| Model | The objects with their statements. |
| State machine | The states with their entry and do blocks and their inner states, the transitions and the macros. |

An attachable state machine shows its name with its types as the detail. A fragment shows its header as a row of its
own above its states, for example `bulb_test : FRAGMENT`. A container state has the fragment it uses as its detail, for
example `self test : USE bulb_test`, and a final state reads `passed : FINAL`.

A click on a row selects the element in the text.

## 4.2.6 Problems

The status bar shows `Problems` at its left end. While the project has errors or warnings, the entry reads
`Problems: N` with the icon of the worst severity, and a click on it shows or hides the *Problems* tool window. Without
errors or warnings the entry takes no click. The tool window hides itself once no problem is left.

The *Problems* tool window has two groups. The group *Local* holds what the editor finds while you type, and *Global*
holds what only a validation of the whole project finds. Before the first validation the group reads
`Global (not validated yet)`. What each kind of check looks at is described in [4.4 Validating](4.4-validating.md).

Within each group the problems are sorted by file. A file is shown as `path (N)` and a problem as
`message (line:col)`. The chips `Errors (N)`, `Warnings (N)` and `Infos` above the list show and hide the problems of
each severity. A double-click or Enter on a problem leads to its place in the text.

The counts in the status bar are those of the group *Local*.

## 4.2.7 Find and replace

The menu entry *Edit > Find…* (Cmd+F / Ctrl+F) opens the find bar. It has three toggles.

- `Aa` for Match Case
- `W` for Whole Words
- `.*` for Regular Expression

Enter or the next button goes to the next match, and Shift+Enter or the previous button goes to the match before.
Escape closes the bar. *Edit > Replace…* (Cmd+R / Ctrl+R) opens the same bar with a second field for the replacement
and the buttons *Replace* and *Replace All*.

*Navigate > Go to Line…* (Cmd+L / Ctrl+G) opens a small field that shows `Current line X of Y`. Enter or the button
*Go* moves the caret to the line typed into the field.

## 4.2.8 Saving and changes outside the IDE

*File > Save* (Cmd+S / Ctrl+S) saves the active file, and *File > Save All* (Cmd+Option+S / Ctrl+Alt+S) saves every
file. A tab with unsaved changes asks before it closes and offers the buttons *Save*, *Don't Save* and *Cancel*. A run
saves every open file before it starts.

A file can also change on disk while it is open in the editor.

| Case | What the editor does |
|---|---|
| The file changes on disk and has no unsaved changes. | It loads the new text as one change. *Edit > Undo* takes the change back. |
| The file changes on disk and has unsaved changes. | A banner above the text reads `<file> changed on disk while it has unsaved changes.` and offers the buttons *Reload* and *Keep mine*. |
| The file is deleted on disk. | A banner reads `<file> was deleted on disk.` and offers *Close* and *Keep mine*. |
| A save would write over a file that changed on disk. | It asks first and offers *Overwrite* and *Cancel*. |

## 4.2.9 Editing a descriptor

A descriptor is edited as JSON text, with completion, hover and go to definition as the tables above describe them.
The editor checks the keys and the kinds of their values, and it checks that every named file exists and is of the
right kind. The keys and the problems of a descriptor are listed in
[4.1.2 Environment descriptors](4.1-projects.md#412-environment-descriptors).

A bridge file has no text editor. It opens in the form of [4.7.4 The bridge form](4.7-bridges.md#474-the-bridge-form).

*Toggle Comment*.
